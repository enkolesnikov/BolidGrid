## 5. Найденные дефекты

Всего найдено **6** дефектов; все исправлены разработчиком и **перепроверены независимо** на живом приложении. Ниже — полные repro и причина.

### BUG-1 — HIGH: «Факт» кабеля в спецификации считался в мм, план — в метрах
* **Где:** вкладка «Спецификация», раздел «Кабельная продукция»; причина — `js/panels.js:655` (`fact = journal.totalsByCable[].length`, мм) при плане в метрах.
* **Repro:** открыть демо-проект → «Спецификация» → «Кабельная продукция».
* **Ожидалось:** поз.13 `КПСнг(А)-FRHF 1x2x0,5` — план 280 м, факт ≈ 12,52, расхожд. ≈ −267,48.
* **Фактически (до фикса):** факт «12 522,5», расхожд. «+12242.5» (красный); поз.14 — «13 638,28» / «+13478.27660925679». Кабельный журнал при этом показывал корректные 12,52 м / 13,64 м. Console чистый — дефект «тихий»; CSV/Markdown наследовали неверные числа.
* **Фикс (c354faa):** мм→м (`length / 1000`), формат `fmt()` для плана/расхождения.
* **Перепроверка:** PASS — 12,52/280/−267,48; в проекте с добавленными ДИП-34А — 14,99/160/−145,01; CSV в метрах.

### BUG-2 — LOW/MED: импорт не ограничивал координаты устройств габаритами стены
* **Где:** `js/store.js` → `sanitizeProject` (не было clamp x/y).
* **Repro:** импорт `{"project":{"walls":[{"id":"w1","width":6000,"height":2700}],"devices":[{"id":"d1","modelId":"dip34a","wallId":"w1","x":99999,"y":-50}]}}`.
* **Ожидалось:** координаты в пределах стены.
* **Фактически (до фикса):** x=99999, y=−50, устройство за листом (визуально отсутствует), сохранялось и в экспорте.
* **Фикс:** clamp `x∈[0,W−w]`, `y∈[0,H−h]` (и `Math.round`) в `sanitizeProject`.
* **Перепроверка:** PASS — 99999/−50 → 5900/0, `rot:45 → 0`.

### BUG-3 — LOW: несогласованное членство групп после импорта
* **Где:** `js/store.js` → `sanitizeProject` (каждая сторона фильтровалась отдельно, не выводилась одна из другой).
* **Repro:** импорт группы с `deviceIds:["d1"]` и устройством с `groupIds:["nope"]`.
* **Ожидалось:** согласованное двустороннее членство.
* **Фактически (до фикса):** `group.deviceIds=["d1"]`, но `d.groupIds=[]` → карточка шлейфа перечисляет устройство, в инспекторе устройства галочка не стоит, цветового маркера нет.
* **Фикс:** источник истины — `group.deviceIds`, `device.groupIds` пересчитывается из групп.
* **Перепроверка:** PASS — `groupDeviceIds=["d1","d2"]`, у обоих `groupIds=["g1"]`.

### BUG-4 — LOW: нумерация обозначений «прыгала» после удаления первой стены
* **Где:** `js/store.js` → `nextTag` (номер брался из индекса стены).
* **Repro:** демо-проект → удалить первую стену → добавить устройство на оставшуюся.
* **Ожидалось:** продолжение существующего семейства (2.x), напр. `2.16`.
* **Фактически (до фикса):** новое устройство получало `1.1`, хотя на стене уже были `2.1…2.15`.
* **Фикс:** продолжение по самому частому существующему префиксу `N.M`.
* **Перепроверка:** PASS — `2.16`, дублей нет.

### BUG-5 — MEDIUM: экспорт SVG отдавал документ без `viewBox`/размера, а самой кнопки в UI не было
* **Где:** `js/wall.js` → `exportSVGFile()`: внешняя обёртка `<svg xmlns=…>` создавалась без `viewBox/width/height`, при этом открывающий тег клона (где эти атрибуты были выставлены) вырезался регуляркой; документация (README/USAGE) обещала «Экспорт SVG», но ни одна кнопка UI его не вызывала.
* **Repro:** `const svg = await window.BolidGrid.editor.exportSVGFile();` → сохранить в файл → открыть в браузере.
* **Ожидалось:** корневой тег с `viewBox`/`width`/`height`, лист виден целиком.
* **Фактически (до фикса):** `<svg xmlns=…>` без `viewBox`, лист 4200×2700 «пикселей»; в окне 1680×1000 виден только левый верхний фрагмент, устройства за кадром. XML при этом валидный и `.dev` внутри есть — поэтому простая проверка «парсится и содержит .dev» дефект не ловила. Скрин: `tests/output/qa-08-export-svg.png` (до/после — см. историю).
* **Фикс (c354faa):** `viewBox/width/height` и `id` вынесены на внешний `<svg>`, стили завёрнуты в `CDATA`, добавлена кнопка «SVG» в топбар (`data-action="export-svg"`, скачивание файла + toast), обновлены README/USAGE.
* **Перепроверка:** PASS — `viewBox="-260 -260 4720 3220"`, `width=1180`, `height=805`, файл открывается как полный чертёж; кнопка «SVG» скачивает валидный `*.svg` (177-й прогон включает этот UI-путь).

### BUG-6 — HIGH: сломанная вёрстка левой колонки на всех проверенных высотах

## 7. Ограничения покрытия и замечания (не блокирующие)

1. **Диалог печати реально не вызывался:** печатные стили проверены через `page.emulateMedia({media:'print'})` (как требует ТЗ). События `beforeprint/afterprint`, системный диалог и PDF-рендер не эмулировались; `window.print()` в тестах не нажимался.
2. **SVG-экспорт проверен только в Chromium:** парсинг XML, `viewBox`, `.dev`, открытие файла как документа. Совместимость с Illustrator/Inkscape/AutoCAD не проверялась; в экспорт встраивается весь `css/app.css` (включая UI-стили) — файл больше, чем нужно для чертежа.
3. **Мёртвая ссылка:** `js/wall.js` (`_finishChannel`) использует `this.lastChannelKind`, который нигде не присваивается → при рисовании всегда создаётся «кабель-канал»; тип меняется только в инспекторе. Косметика, на функциональность пунктов ТЗ не влияет.
4. **Кнопки undo/redo всегда активны** (нет disabled-состояния); при пустой истории показывается toast. Косметика.
5. **Поворот устройств не учитывается в clamp:** координаты ограничиваются неориентированным габаритом `model.w/h`; при `rot=90/270` устройство может визуально выступать за край стены. В ТЗ не входило, отдельно не проверялось.
6. **Не покрыто:** реальные touch/pen-события, viewport < 1280 px (адаптив 1150/1400), производительность на сотнях устройств, экспорт в сторонние редакторы, доступность (screen reader).
7. **Гигиена репозитория:** в коммите `c354faa` случайно оказались мои временные probe-скрипты `tests/_probe*.mjs` (они удалены в рабочем дереве) и промежуточная версия `tests/qa.mjs`. Актуальные файлы — в рабочем дереве: `tests/qa.mjs` (B15 через настоящий клик + тест кнопки «SVG»), `tests/_probe*.mjs` — удалены. Разработчику стоит закоммитить рабочее дерево (`tests/qa.mjs`) и удаление probe-файлов; `tests/output/` — в `.gitignore`.
