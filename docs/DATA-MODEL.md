# Формат проекта BolidGrid

Файл проекта — JSON. Экспорт: кнопка «Экспорт»; импорт: кнопка «Импорт».
Автосохранение в браузере хранит тот же объект `project` в `localStorage`.

## Система координат

- Единицы — **миллиметры**.
- `x` — расстояние вдоль стены от левого края листа.
- `y` — высота **нижней грани** устройства от уровня пола (`0,000`).
- Габариты устройства берутся из каталога (`js/catalog.js`, поля `w`, `h`);
  при изменении модели координаты пересчитываются и ограничиваются листом стены.
- Точки канала `points` — `[x, высота_от_пола]`, ломаная минимум из двух точек.

## Справочники

| Поле | Значения |
|---|---|
| `devices[].modelId` | id модели из `js/catalog.js`: `sirius`, `dip34a`, `ipr513`, `sp2`, `sp4_220`, `ar2`, `mpn`, `molnia_exit`, `molnia_dir`, `mayak`, `kmo2k`, `akb`, `kdl`, `sp1`, `s2000m`, `rip12`, `bp12`, `switch`, `socket`, `custom` |
| `channels[].kind` | `кабель-канал`, `лоток`, `гофра`, `труба` |
| `groups[].kind` | `ШС`, `СОУЭ`, `Питание`, `Адрес`, `Прочее` |

## Соответствие спецификации

У моделей каталога есть поле `specPos` — номер позиции в спецификации
(`data/spec.json`, позиции 1–12 для оборудования, 13–14 кабели, 15–25 материалы, 26–30 запчасти).
Сопоставление «по спецификации / фактически» идёт по номеру позиции, поэтому
переименование модели в каталоге не ломает расчёт.

Позиция 12 спецификации имеет вид `akb`, в каталоге — вид `bp` (питание/АКБ);
связь выполняется по `specPos`, а не по виду устройства.

## Совместимость

`version: 1`. При загрузке файла выполняется нормализация: неизвестные модели заменяются
на `custom`, координаты ограничиваются, «висячие» ссылки на устройства/группы удаляются.
Неизвестные поля игнорируются.
