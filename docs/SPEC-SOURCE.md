## 2. Почему понадобился свой декодер

Встроенный шрифт PDF (`ISOCPEUR`, подмножество `/tmp/fonts/46_ISOCPEUR.ttf`) имеет
битую карту `ToUnicode`: для большинства глифов `pymupdf`/`pdftotext` отдают
`U+FFFD` (в тексте — «квадратики»), поэтому обычное извлечение даёт текст с
пропущенными буквами («Прибор приемно контрольный…», «����» вместо кодов).

Текст восстановлен по **именам глифов** (glyph names) из самого подмножества шрифта:

- кириллица — имена вида `uni0410`, `uni043C` → код символа;
- латиница, цифры, пунктуация — через `fontTools.agl.toUnicode()`
  (`A`, `two`, `parenleft`, `quotedbl`, …); первая версия декодера знала только
  цифры/пунктуацию, из-за чего терялись латинские буквы (M, A, C, D, F, R, X, x, d…);
- координаты каждого спан-фрагмента (`bbox`) использованы, чтобы разложить текст
  по столбцам таблицы, а не «в строку».

Рабочий декодер добавлен в репозиторий: **`tools/pdf_decode.py`** (сам вытаскивает
встроенный шрифт из PDF, поэтому не зависит от временных файлов). Запуск:

```bash
python3 -m pip install pymupdf fonttools
python3 tools/pdf_decode.py "ДФО СПС.СОУЭ -г.Елизово л.pdf" --pages 19 20 -o spec-table.txt
```

Исходный PDF в репозиторий не включён (документация заказчика); в `data/spec.json`
сохранён результат извлечения.

Границы столбцов таблицы взяты из её векторных линий (стр. 19):
`121,9 | 459,6 | 623,9 | 726,2 | 853,4 | 918,7 | 983,9` →
*Позиция | Наименование | Тип, марка, обозначение | Код оборудования | Завод-изготовитель |
Единица измерения | Количество*.

Контроль: все 30 строк, извлечённые программно по геометрии столбцов, сравнены с
`data/spec.json` — расхождений нет, кроме перечисленных ниже сознательных
нормализаций (п. 3) и многострочной ячейки поз. 16 (проверена по рендеру страницы).

**Итог по восстановлению:** после исправления декодера **невосстановленных глифов
не осталось** — ни в наименованиях, ни в обозначениях, ни в кодах; заполнитель `?`
нигде не понадобился. Спорные места (см. п. 3) — это не потерянные символы, а
особенности набора самого документа. Файлы `/tmp/decode3.py`, `/tmp/spec_clean2.txt`,
`/tmp/fonts/46_ISOCPEUR.ttf` — временные, вне репозитория; при необходимости декодер
воспроизводится по описанию выше.

## 3. Что неоднозначно / что именно напечатано в PDF

**Нормализовано (сознательно):**

1. **Кавычки.** В PDF набраны прямые кавычки-«лапки» (глиф `quotedbl`): `ЗАО НВП "БОЛИД"`.
   В JSON — типографские `«…»` согласно требуемой схеме (`ЗАО НВП «БОЛИД»`).
2. **Дефисы в названиях.** PDF печатает `приемно - контрольный`, `охранно - пожарный`
   (с пробелами вокруг дефиса, поз. 1, 8, 9, 28, 29). В JSON — `приемно-контрольный`,
   `охранно-пожарный` (как в образце поз. 1 из задания). Прочие дефисы в моделях
   (`С2000-СП4/220`, `ДИП-34А-04`) в PDF и так без пробелов.
3. **Двойные пробелы** внутри ячеек («скобы СМО   d19-20») сведены к одинарным;
   в названии помещения «Комната приема пищи/ Гардероб» (в PDF пробел после «/»)
   оставлен вариант без пробела — `Комната приема пищи/Гардероб`, как в списке
   помещений из задания.
4. Заголовок группы 1: в PDF последняя буква «СПС» набрана **латинской** `C`
   (`СП` + `C`). В JSON — кириллическое `СПС`.

**Напечатано в PDF именно так (сохранено дословно, не «исправлено»):**

5. **Поз. 5.** В графе «Наименование» — родовое `Блок контрольно-пусковой адресный`,
   а конкретное изделие стоит в графе «Тип, марка, обозначение»: `С2000-СП4/220 исп.01`.
   (Для сравнения, поз. 4: `Блок сигнально-пусковой адресный` / `С2000-СП 2`.)
6. **Поз. 4.** Модель напечатана с пробелом: `С2000-СП 2` (глиф пробела между `СП` и `2`
   присутствует в PDF). В JSON оставлено как напечатано.
7. **Поз. 15.** В графе «Код оборудования» — `PR.012031м`: после артикула стоит
   кириллическая `м` (похоже, единица измерения «затесалась» в ячейку кода; в графе
   «Ед. изм.» тоже стоит `м`). Артикул — `PR.012031`. В JSON код сохранён дословно.
8. **Позы. 17–21.** Артикулы (`CM410831`, `CM200802`, `CM100800`, `07-0208-5`,
   `07-6236`) напечатаны в графе «Тип, марка, обозначение», графа «Код оборудования»
   пустая. В JSON они в поле `model`, `code` = "".
9. **Позы. 23 и 25** — одинаковое наименование `Пена однокомпонентная огнезащитная,
   баллон 740 мл`, но разные коды: `DF1201` (2 шт.) и `DF1202` (2 шт.). Так в PDF,
   строки не объединялись.
10. **Поз. 12.** Завод-изготовитель — `Delta`, модель `DELTA HRL 12-18 X`
    (латиница вперемешку с цифрами; в PDF так же).
11. **Поз. 22.** Название и модель набраны без пробела перед «мм»: `25х2мм ГОСТ 8734-75`
    (в поз. 20 при этом `4,6х200 мм` — с пробелом).
12. **Поз. 13/14.** `FRHF (1x2x0,5)` / `FRHF (1x2x0,75)` — латинская `x`; в поз. 18/20/22
    знак умножения набран **кириллической** `х` (`M8х2000`, `4,6х200`, `25х2`).
13. **Символ диаметра.** В поз. 15/16 напечатана латинская `d`, а не `⌀`:
    `d20 мм`, `d19-20 мм`.
14. **Кавычки в названиях** поз. 1, 8, 9, 28, 29 — `"Сириус"`, `"ВЫХОД"`,
    `"НАПРАВЛЕНИЕ ДВИЖЕНИЯ"` (прямые), в JSON — `«Сириус»`, `«ВЫХОД»`,
    `«НАПРАВЛЕНИЕ ДВИЖЕНИЯ»`.
15. `Молния - 24 Ultra` — с пробелами вокруг дефиса (позы. 8, 9, 28, 29), сохранено.
16. `ИПР-513-3 АМ исп.01` — с пробелом между `513-3` и `АМ`, сохранено.
17. `КМ-О (2К) IP 41` — кириллическая `О`, латинские `IP`; сохранено.

**Пустые графы.** Столбцы «Масса, кг» и «Примечания» в таблице есть, но **не заполнены
ни для одной позиции** — в JSON они не выводятся.

**Позиции и количества.** Все 30 позиций присутствуют, нумерация 1…30 непрерывная,
количества перенесены из графы «Количество» цифрами (напр. поз. 2 — 32 шт.,
поз. 15 — 530 м). Ничего не добавлялось и не досчитывалось.

## 4. Экспликация помещений (лист 4, стр. 14)

Таблица «ЭКСПЛИКАЦИЯ ПОМЕЩЕНИЙ» (колонки: № пом. | Наименование | Площ. м²).
**Номера помещений и площади в этой таблице нарисованы векторными контурами, а не
текстом** — в текстовом слое PDF их нет, извлекаются только наименования. Поэтому
таблица прочитана с рендера страницы (300–420 dpi) и сверена с планом.

| № пом. | Наименование | Площадь, м² |
|---|---|---|
| 101 | Операционный зал | 89,18 |
| 102 | Кабинет директора | 12,36 |
| 103 | Переговорная ПМУ | 9,30 |
| 104 | Кроссовая/Пультовая БЭК офис без РМ | 4,92 |
| 105 | Комната приема пищи/ Гардероб | 21,17 |
| — | ИТОГО | 136,92 |
| — | Площадь клиентской зоны | 110,20 |
| — | Площадь бэк зоны | 26,1 |

Перенесено в `rooms`: 5 помещений + 2 итоговые строки зон. Строка «ИТОГО» в `rooms`
не включена (не помещение; 89,18+12,36+9,30+4,92+21,17 = 136,93 — в документе
напечатано 136,92, расхождение округления самого документа).

**`Электрощитовая`** присутствует только как подпись помещения **на плане** (лист 4);
в таблицу-экспликацию она не входит, площадь не указана → `area: null`,
отмечено в `note`. Добавлена в `rooms` по требованию задания.
