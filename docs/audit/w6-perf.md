# W6 — производительность и рендер панелей

Дата: 2026-11-14. Ветка: `main`, версия 1.8.0. Зона правок: `js/panels.js`,
`js/catalog.js`, новый `tests/perf.mjs`, этот отчёт.

> Замеры сделаны на рабочем дереве, где параллельно шли правки других агентов
> (`css/app.css`, `index.html`, `js/main.js`, `js/store.js`, `js/wall.js`).
> Метрики панелей (`renderAll`, `renderFor`, `renderPalette`, узлы DOM, вызовы
> скрытых вкладок, фокус) относятся только к `panels.js`/`catalog.js` и
> сопоставимы. Сквозной `commit` включает `editor.render()` из `wall.js`,
> поэтому он приведён справочно и может меняться от чужих правок.

## Стенд

- Node 24.19.0, Playwright 1.64.1, headless Chromium, `--no-sandbox`.
- Viewport 1680×1000, собственный статический сервер на случайном порту.
- Демо-проект: 6 приборов, 1 стена, спецификация из `data/spec.json`.
- «100 приборов»: демо + 100 моделей (`sp2`, `sp4_220`, `ar2`, `sirius`,
  `mpn`, `molnia_exit`) одним `store.act`, итого 106 приборов.
- Время — медиана 7–9 прогонов после двух «прогревочных» вызовов, мс.
- Скрипт замера: вне репозитория (`/tmp/opencode/measure.mjs`); в репозитории
  остаётся воспроизводимый тест `tests/perf.mjs`.

## Что изменено

### `js/panels.js`

1. **Делегирование событий палитры** — `_bind()` (`js/panels.js:73-99`):
   один `click` на `#palette-list` (модель + заголовок группы), один `keydown`
   (Enter/Space по группе) и один `click` на `#palette-groups` (фильтр систем).
   Удалены `querySelectorAll(...).forEach(addEventListener)` из конца
   `renderPalette()`: на 22 кнопки и 5 групп больше не навешивается 32
   обработчика после каждого `innerHTML`.
2. **Подпись палитры** — `renderPalette()` (`js/panels.js:277-357`):
   - `structKey` (поиск, фильтр, свёрнутость, `placeSystem`) — при совпадении
     DOM не трогается вовсе;
   - `countsKey` (размещено / по спецификации) — при изменении только счётчиков
     обновляются лишь содержимые `.pcount` (`_updatePaletteCounts`,
     `js/panels.js:367-377`), кнопки и фокус сохраняются;
   - смена `armed` — только переключение класса `.armed` без пересборки.
3. **Ленивые скрытые вкладки** — `_markTab()` (`js/panels.js:222-228`),
   вызовы из `renderFor('project'|'spec')` (`js/panels.js:185-215`) и
   дорисовка в `setTab()` (`js/panels.js:161-171`). Спецификация и ведомость
   помечаются dirty на commit и рендерятся при активации вкладки (desktop-таб
   или мобильная шторка — обе идут через `setTab`). `renderSpec`/`renderJournal`
   снимают флаг в конце (`js/panels.js:830`, `js/panels.js:987`).
4. **Фокус и каретка в инспекторе** — `renderInspector()` (`js/panels.js:393-424`),
   `_inspectorFieldKey` / `_captureFocus` / `_restoreFocus`
   (`js/panels.js:427-475`). Перед пересборкой запоминается устойчивый ключ поля
   (`data-f`, `data-pos-x`, `data-ch-point`+`data-axis`, …), позиция каретки и
   `scrollTop`; после — поле получает фокус и каретку обратно.
   Разметка инспектора сравнивается с предыдущей, и при совпадении DOM не
   пересобирается (важно: иначе восстановление фокуса на странице с 100
   приборами стоило 12–15 мс на каждый commit).
5. **U-08: строки стен** — `renderWalls()` (`js/panels.js:245-265`):
   `role="button" tabindex="0"` у `.wall-item`; `keydown`-делегирование
   Enter/Space в `_bind()` (`js/panels.js:143-152`). Вложенная кнопка удаления
   исключена из клавиатурной активации стены (`closest('[data-wall-del]')`) и
   продолжает открывать подтверждение. Фокус строки переживает перерисовку.

### `js/catalog.js`

6. **Кэш миниатюр** — `modelThumb()` (`js/catalog.js:193-205`): SVG символа
   строится один раз на пару «id модели + размер» вместо каждого рендера
   палитры.
7. **Предвычисленный haystack поиска** — `modelHaystack()`
   (`js/catalog.js:420-426`): строка `name + model + full + vendor` в нижнем
   регистре считается один раз при загрузке модуля, а не для каждой модели на
   каждый ввод.

## Что не дало измеримого выигрыша / отклонено

- **Кэш `modelThumb` + haystack** дают скромный эффект: полная пересборка
  палитры 2,5 → 1,7–2,1 мс (20–30 %), на части прогонов разница в пределах шума.
  Оставлены, потому что убирают повторную генерацию SVG и аллокации строк, но
  как самостоятельная оптимизация это не «победа» — основной выигрыш даёт
  отсутствие пересборки.
- **Поиск** по-прежнему требует полной пересборки палитры: меняется состав
  моделей, точечного обновления недостаточно. Это осознанно: 1,7–2,1 мс на
  запрос, кэш haystack лишь немного снижает стоимость.
- **Синхронное восстановление `scrollTop`** после `innerHTML` вызывало
  принудительный layout (~5 мс на большом листе). Перенесено в
  `requestAnimationFrame`; фокус и каретка восстанавливаются синхронно, прокрутка
  — в следующем кадре.
- **Полная пересборка инспектора с восстановлением фокуса на каждый commit**
  оказалась регрессом (renderFor 0,2 → 15–22 мс на 106 приборах). Поэтому
  добавлено сравнение разметки: пересборка и восстановление фокуса происходят
  только когда содержимое инспектора реально изменилось.
- **Кэширование пустого инспектора** (там `findPlacementIssues()` — O(n²) в
  `store.js`) не делалось: это чужая зона (`store.js`), а выигрыш в замерах
  мал по сравнению с риском пропустить изменение пересечений.

## Тест `tests/perf.mjs`

Собственный сервер на случайном порту (20000–39999), Playwright, ненулевой
exit при провале. Проверки:

- `renderAll` на демо и на 106 приборах < 300 мс (факт 1,5–1,8 / 3,0–3,2 мс);
- `renderFor('project')` на 106 приборах < 50 мс (факт 0,4–0,5 мс; порог в ~100 раз
  выше факта — ловит возврат полной пересборки, но не шум CI);
- `renderPalette()` без изменений < 2 мс и 0 добавленных узлов;
- поиск «2000» даёт ровно ожидаемый состав и порядок моделей;
- скрытые `renderSpec`/`renderJournal` не вызываются на commit (0/0), DOM
  спецификации не меняется, а при открытии вкладки «Факт» догоняет +3;
- фокус и позиция каретки в поле обозначения сохраняются, значение
  коммитится;
- `.wall-item` имеет `role="button"`, `tabindex="0"`, Enter/Space переключают
  стену, кнопка удаления по-прежнему открывает подтверждение;
- нет `pageerror` и `console.error`.

Результат прогона: 21 PASS, 0 FAIL, exit 0. Два первых прогона поймали ошибки
самого теста, не кода: (1) ожидаемый состав поиска строился в порядке
`MODELS`, а палитра группирует по `SYSTEM_ORDER` — тест теперь повторяет
порядок отображения; (2) проверка сохранения обозначения читала уже
мутированный объект устройства (`device.tag` менялся тем же commit) —
ожидаемое значение теперь фиксируется до `change`. Оба исправления только
уточняют ожидания, проверки не ослаблены.

## Остающиеся ограничения

- `renderFor('wall')` не помечает спецификацию dirty: «Факт» в спецификации
  считается по всему проекту, а ведомость коробов — по всем стенам, поэтому
  смена активной стены их содержимое не меняет. Если это правило изменится,
  `_markTab` нужно добавить и в ветку `'wall'`.
- Клавиатурный фокус на строке стены сохраняется по `data-wall-id`; после
  удаления стены фокус уходит на `body` — это ожидаемо.
- Сквозной commit по-прежнему в основном тратит время в `editor.render()`
  (`js/wall.js`) и `findPlacementIssues()` (`js/store.js`); это вне зоны W6.
